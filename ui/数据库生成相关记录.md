## 关键设计

- **主键选用 `taskId`**：与 `TaskScheduler` 中 `taskId -> DownloadTask` 的一对一关系一致，避免 `@Upsert` 因唯一索引冲突触发 REPLACE 从而级联删掉分块记录（原 `recordId` 自增主键在 `task_id` 唯一约束下存在该隐患）。
- **表字段严格对齐模型**：文件信息取自 `AndroidDownloadParams.FileEntity`（url/mimeType/name/size/description/version/versionCode/date/md5），任务配置取自 `DownloadTaskConf`（dirPath/chunk 相关），状态进度取自 `DownloadStatus.DOWNLOADING`，`AndroidPath` 拆成 `path_type + path_value` 两列。
- **状态无法直接持久化**：`DownloadStatus.ERROR` 携带 `Throwable`，故用 `DownloadStatusType` 记录状态、`error_message` 记录异常信息。
- **分块进度独立成表**：对应 `ChunkProgress`，主键 `(task_id, chunk_index)`，`OnDelete CASCADE`；`saveTask`/`replaceChunks` 用 `@Transaction` 保证“先清后写”。
- **高频写用局部更新**：`updateProgress`、`updateStatus`、`updateQueueOrder`、`markStarted`、`markEnded` 只更新相关列；`queue_order` 保存 `TaskSchedulerSaveState.pending` 的排队顺序（-1 表示不在队列）。
- **可逆映射**：`DownloadTaskSaveState.toTaskEntity(...)` / `toChunkEntities()` 用于落库，`DownloadTaskWithChunks.toSaveState()` / `toDownloadParams()` 用于恢复任务与断点续传。

## 使用示例

```kotlin
val dao = DownloadTaskDatabase.getInstance(context).downloadTaskDao()

// 从服务快照落库
val state = linker.saveState()
state.taskSchedulerSaveState.all.forEachIndexed { index, save ->
    val params = state.infoMap[save.id]
    dao.saveTask(save.toTaskEntity(params, queueOrder = index), save.toChunkEntities())
}

// 恢复
val records = dao.getAllWithChunks()
records.firstOrNull()?.let { record ->
    val task = DownloadTask(record.toSaveState())
    val params = record.task.toDownloadParams()
}
```

注意：`ui/schemas/.../1.json` 已随编译生成，但你本机全局 `~/.gitignore` 含 `schemas/` 规则，若要提交迁移 schema 需 `git add -f` 或调整忽略规则。
